# Remote Control Studio 演示边界与演进方案

## 本轮目标

本轮把既有 PC 服务、手机常驻客户端和 `ws-scrcpy` 串成一个可本地演示的服务端中继闭环：

- `http://127.0.0.1:3000/studio/` 是统一入口，PC 服务同时承担临时会合与有界二进制中继；
- `http://127.0.0.1:8000/` 只承载本地调试版 `ws-scrcpy` 网页资源；服务端中继模式不走其 ADB proxy；
- 手机通过 MQTT 收到短时邀请后，主动连接服务端 WSS，再桥接本机回环 `ws://127.0.0.1:8886/`；
- 浏览器领取独立的一次性票据后主动连接同一 WSS，票据只经父页面内存 `postMessage` 交给 iframe；
- 所有运维 HTTP 请求都只异步受理，调用方使用 `taskId` 轮询终态；
- 行为录制、剪辑、回放和代码生成在浏览器本地完成，不上传到服务端。

这是一套单机调试版，不是多租户权限系统。角色页签用于展示不同工作流，不能当作访问控制。

## 能力矩阵

| 角色 | 演示能力 | 数据边界 |
| --- | --- | --- |
| 运维 | 自由远控；能力清单；网卡 IP、Wi-Fi 与蜂窝信号；掩码电话信息；亮度；铃声音量读取；前台应用；振动通知寻机；临时截图 | 固定操作白名单；不接受 Shell、JavaScript、任意路径和任意文件读取 |
| 产品 | 浏览器操作录制；显式文本动作；可选 WebM；逻辑动作时间线；删除动作；撤销/重做；控件识别；保存、载入、删除；JSON 导入导出；带动作提示的回放 | 项目只存在当前浏览器 `localStorage`，最多 25 条；视频只在内存，需手动下载；控件识别读取手机当前页面，不重建历史页面 |
| 开发 | 把剪辑后的动作生成选择器优先的 AutoJS6 JavaScript 草稿 | 默认仅选择器；普通动作可显式允许缩放坐标兜底；发送/发布等外部写入禁止坐标兜底；仅下载草稿，不自动执行 |
| AI | 本地检查弱选择器、坐标脆弱、长等待、未闭合动作和疑似敏感输入 | 当前是确定性规则，不调用模型、不上传录制；后续模型只能给建议或产出待审核草稿 |

## 运行拓扑

```text
Browser /studio + ws-scrcpy iframe
  |  HTTPS: create/poll/close lease
  |  WSS: controller hello + binary control/video
  v
Public rendezvous / relay service
  |-- MQTT OPEN_REMOTE_SESSION --> phone daemon
  |<---------------- phone outbound authenticated WSS
  |                                |
  |                                `-- loopback WS --> scrcpy server on Android
  `-- ordered, bounded binary relay --^
```

控制面始终经过服务端。当前基线数据面也经过服务端，所以手机和 PC 只需分别具备到同一公网 HTTPS/WSS 服务的出站能力；两端无需互相发现局域网地址，AP 隔离、不同 NAT 或不同运营商网络都不改变协议。运维任务仍是结构化、可审计的短时操作；原始画面/控制帧只透明中继，不会被服务端解释成 Shell 或脚本。

本机 ADB 路径继续存在，但在界面上明确标为调试适配器。正式给不同用户使用时，应把 PC 服务部署为 TLS 公网网关，并把 `ws-scrcpy` 静态资源置于受控 Web 源；不能暴露手机回环 scrcpy 端口，也不能把一次性票据放进 URL、日志或浏览器存储。

## 演示流程

1. 启动 PC 服务和 `ws-scrcpy` 静态页，确认端口分别为 `3000`、`8000`；手机上的 scrcpy WebSocket 只监听回环 `8886`。
2. 本机验证时可执行 `adb reverse tcp:3000 tcp:3000`，让手机把回环 `3000` 当作公网服务入口。它只是开发环境入口映射，不是浏览器到手机的数据直连。
3. 打开 `/studio/`，填写手机 MQTT Client ID、ADB Serial 和 PC API Token。
4. 在运维页执行能力清单与设备概览；页面应先显示 `EXECUTING`，再显示手机终态。
5. 点击“服务端中继”，确认会话依次进入等待手机、等待另一端和 `ACTIVE`，并通过浏览器做一组低风险操作。
6. 验证会话字节统计增长；移除 PC 上仅供旧直连使用的精确 ADB forward 后，中继画面和控制仍应继续工作。
7. 在 Studio 右侧产品工作台开始录制；需要输入文本时聚焦手机输入框，再使用“输入并记录为文本动作”，该按钮只输入文字，不点击发送。
8. 停止录制后选择一个点击动作，把手机返回该动作所在页面，再执行“识别所选控件”；根据风险选择失败策略，发送/发布类动作标记为“外部写入”。
9. 选择并删除一个动作、撤销，再重新删除；保存并重新载入项目。普通动作可按原时序回放并显示叠加提示；只要存在未删除的外部写入动作，原始控制包回放必须保持禁用。
10. 下载项目 JSON 和选择器优先 AutoJS6 草稿；确认外部写入没有坐标兜底、歧义选择器会停止；如浏览器支持，再单独验证 WebM 下载。
11. 查看本地审计结论，确认敏感文本只报告类型/长度，不显示原值。

`adb reverse` 验证只能证明本机三端实现与服务端中继协议闭环，不能替代公网 TLS、跨运营商网络、代理超时和容量测试。

## P2P 数据通道

服务端中继仍是默认基线。选择“自动（P2P 优先）”、服务端显式开启 feature gate 且双方都协商
`autojs6-remote-v2` 时，浏览器 WebRTC 与手机 Pion sidecar 通过 WSS 交换受限 SDP/ICE，再以一个
可靠、有序的 `RTCDataChannel` 承载 scrcpy 二进制。最终选路完成前不会启动数据面，因此不会把
同一 scrcpy 流同时写入 P2P 和 WSS。

STUN 只帮助发现候选地址，不保证能穿过对称 NAT、企业防火墙或受限 UDP。本阶段不部署 TURN；
ICE 失败或十秒超时会选择现有 WSS relay。P2P 运行中失效时，Studio 冻结输入，手机重建本地
scrcpy，服务端收到 device 的 relay-ready 确认后恢复 WSS 数据。录制工作区保留并增加非执行型
transport interruption marker。开启 P2P 可能向对端暴露网络候选信息，因此必须由租户策略显式
启用，服务端只记录候选类型与 UDP/TCP，不记录 SDP、candidate IP 或一次性票据。

## 多用户包装建议

正式给不同用户使用前，至少增加以下服务端边界：

- SSO 与真实 RBAC；`ops`、`product`、`developer`、`ai` 权限由后端判定；
- 每台设备同一时刻只授予一个带过期时间的控制租约，旁观者只读；
- 设备、用户、会话、动作摘要、审批与结果形成追加式审计记录；
- 录像与项目使用独立存储对象、租户前缀、生命周期和删除凭证；
- 高风险动作要求二次确认或审批，敏感字段默认脱敏；
- `ws-scrcpy` 由鉴权网关代理，原始端口继续只监听回环地址；
- AI 只能调用与当前角色相交的白名单工具，生成的脚本先静态检查再人工批准。

浏览器 `localStorage` 适合本地演示，但不具备共享、版本、权限、审计或可靠备份能力。正式版的产品回放应迁移到服务端项目模型，同时保留不可变原始事件和独立的编辑决策列表。

## 从录制到代码

原始录制继续保存不可变的 scrcpy 控制消息；Studio schema v2 另外保存稳定动作 ID 对应的语义注解。对有坐标的动作，手机以只读 `device.ui.target-at` 操作抓取当前 `uiautomator` 层级，在手机端完成命中、文本隐私分类和大小限制后，仅返回单个目标摘要。控件 ID、文本、类型与边界必须来自同一个节点；仅严格白名单中的通用控件文案可以作为 literal，其余短文本也默认脱敏。完整 XML、页面源码和候选列表不会进入 PC、项目 JSON 或父子页面消息协议，失败响应也只能携带空对象。

生成 AutoJS6 草稿时按资源 ID、描述、已复核文本、控件类型与归一化边界逐级定位。普通动作的完全匹配出现多个候选时，可使用录制边界选择最近项，但候选过于接近会返回失败。默认策略是“仅选择器”，普通动作可由产品显式允许选择器失败后使用分辨率缩放坐标；标记为外部写入的动作强制仅选择器、禁止 class-and-bounds，并要求强选择器只命中一个节点，多候选无论距离多远都停止。Android Activity 的短类名、组件名和完整类名会先规范化再比较。

录制中通过专用文本控件写入手机当前焦点时，会同时形成一个真实 `TYPE_TEXT` 事件，因此代码可以生成集中管理的输入常量，而不是尝试从软键盘点击猜字。旧录制如果只有软键盘坐标，本身没有字符信息，导入迁移也不能还原缺失文本，必须补录文本动作或由开发手动补参数。

Appium 不进入手机正式执行链路。它适合作为独立的桌面验收/回归层，用来验证生成草稿在测试设备上的页面定位；正式运行仍保持 ws-scrcpy 录制、受限设备查询和 AutoJS6 执行三层边界。

## 语音转发结论

现代官方 scrcpy 支持 Android 11 及以上的设备音频转发，也支持选择麦克风等音频源；但当前嵌入的 `ws-scrcpy` 使用旧的 scrcpy 1.19 派生协议。音频不是替换一个 server JAR 就能安全获得：还要同步升级设备端协议、增加独立音频流、浏览器解码、时钟同步、静音与权限策略。

因此本轮只保留演进位置，不实现语音转发。建议二期先做单向设备音频监听，再评估麦克风上行或双向通话；后两者还需要更严格的显式授权、可见录音状态和审计策略。

## 已知限制

- 手机上直接发生的物理触摸不会经过浏览器，因此不会进入行为录制。
- 控件识别读取手机当前页面，不保存历史 UI 树；停止录制后识别时需要先把手机返回相同页面。
- 选择器可能随 App 更新失效；默认行为是安全停止，只有普通动作经显式配置后才允许坐标兜底。
- 第一版不会猜测哪个点击代表发送、发布或付款；产品需要把这类动作显式标记为“外部写入”。
- 旧项目中的软键盘坐标无法反推出已输入文字；迁移不会伪造文本语义。
- WebM 是原始渲染画面，不会随时间线删动作，也不会烘焙动作标记。
- 旧版 scrcpy 1.19 在 Android 13 会记录剪贴板监听 API 的兼容性异常；Android 13 测试机上画面与按键控制不受影响，但剪贴板读写不在本轮验收范围内。
- 临时运维任务和截图只在 PC 内存保存，进程重启后消失。
- 本地调试用 `adb reverse` 模拟手机到服务端的出站入口，不代表公网部署、TURN 或跨运营商链路已经完成或安全。
